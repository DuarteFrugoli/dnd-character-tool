1. base45 pode fazer os qrcodes ficarem mais eficientes em 22% de espaço — mas não há pacote confiável no pub.dev e o gzip + base64url já cobre a grande maioria dos personagens dentro do limite do QR v40.
2. Modo aleatório descartado para v1: o wizard guiado é rápido o suficiente. A questão em aberto é definir o quão aleatório o personagem deve ser para ainda ser jogável (atributos ruins, combinações desequilibradas, etc.).
3. **i18n — dados do modelo devem permanecer em inglês.** Todos os valores internos do `Character` (atributos, perícias, classes, raças, backgrounds) devem ser armazenados em inglês, pois são usados em comparações de lógica de negócio e em export/import. A tradução deve acontecer **apenas na camada de UI**, via um mapa `SrdLabels` (ex: `SrdLabels.ability('strength', l10n) → 'Força'`) com fallback para o valor bruto. Isso permite trocar idioma sem migrar dados e mantém export/import compatível entre usuários de idiomas diferentes.
4. no futuro posso permitir exportar magias e outras coisas customizadas para o app de outro usuário usando qrcode ou token ou json.
